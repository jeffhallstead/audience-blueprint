# Reposition Publisher Blueprint as a consultative lead magnet

## Goal

Convert the current product-led funnel (free Publisher Test → $49 Blueprint → optional OS) into a sales-led funnel where the Publisher Test is the only public experience, and the full Blueprint deliverable is reserved for prospects who book a call. Only internal users (admin + a new internal role) can run Blueprint reports or use the OS.

## Strategic summary

- **Publisher Test** stays free and public. It is the lead magnet.
- **Full Blueprint** (executive dashboard, 90-day roadmap, opportunities, AI, exports, PDF, email) becomes an internal deliverable generated by Jeff or a sales rep during or after a sales call.
- **Publisher OS** is not sold publicly. It is kept for internal/admin use only.
- **No paid upgrade path** for regular users. The only CTA from the free results is "Book a call" to `jeffhallstead.com/contact`.
- Existing paid Blueprint/OS customers should be handled deliberately (see Decision 1).

## Technical changes

### 1. Entitlement model

- Add a new `app_role` value, e.g. `internal`, alongside `admin`.
- Introduce `isInternal()` and `isAdminOrInternal()` helpers in `src/lib/admin/shared.ts`.
- Update `resolveEntitlement` so that only users with `admin` or `internal` roles receive `tier = "blueprint"` or `tier = "os"`.
- Remove the automatic tier elevation from `purchases` and `subscriptions` for non-internal users. Purchases can remain recorded for historical/compliance reasons, but they no longer grant feature access.
- Update `requireFeature` to allow only internal users through Blueprint-gated features.

### 2. Public-facing commerce

- Remove the Blueprint product card from `src/routes/pricing.tsx`.
- Repurpose the pricing page as a "Work with Jeff" page that explains the free Publisher Test and the consulting call, with a single CTA to `jeffhallstead.com/contact`.
- Disable the public checkout flow: remove the "Unlock for $99/$49" CTAs from the dashboard and results page.
- Hide or disable the Stripe checkout dialog for non-internal users. Keep the code path for admin/internal grants only.
- Update `src/lib/commerce/plans.ts` so the public `PLANS` array only contains the free Publisher Test; Blueprint and OS are removed from public-facing pricing.

### 3. Marketing site and CTAs

- **Landing page (`src/routes/index.tsx`)**: keep the Publisher Test as the primary CTA, but add a secondary "Book a call" CTA. Update the final section copy to explain that the Blueprint is delivered during the call.
- **Persona cards (`src/components/marketing/persona-cards.tsx`)**: change CTAs from "Start the free Publisher Test" to "Book a call" for P1–P4, and keep the test CTA for P5–P6.
- **Persona banner (`src/components/blueprint/persona-banner.tsx`)**: for P1–P4, change CTA to "Book a 20-minute call" → `jeffhallstead.com/contact`; for P5–P6, keep the test CTA.
- **Header/footer**: replace the "Pricing" link with "Work with me" or "Book a call".
- **SEO metadata**: update the pricing page title/description from "Plans & Pricing" to "Work with Jeff".

### 4. Dashboard and post-assessment flow

- **Dashboard (`src/routes/_authenticated/dashboard.tsx`)**: free users see only the Publisher Index score, maturity level, and category breakdown (the current "locked" preview). Remove the "Download PDF" and "Email my report" buttons. Replace the locked-state upgrade CTA with a "Book a call to receive your full Blueprint" CTA.
- **Results page (`src/routes/_authenticated/results.tsx`)**: after completing the test, show the free Publisher Index results. Change the bottom CTA from "Continue to dashboard" to "Book a call to review your full Blueprint".
- **Welcome page (`src/routes/_authenticated/welcome.tsx`)**: keep the assessment start flow, but update the "Skip to dashboard" copy to reflect that the dashboard shows the free score summary.
- **Locked features**: all Blueprint features (`full_dashboard`, `roadmap`, `ai_documents`, `ai_chat`, `pdf_export`, `file_export`, `email_report`, `connector_export`) remain locked for non-internal users.

### 5. Internal/admin tooling

- **Admin console**: add a "Generate Blueprint" action per user so admins can produce the full report for a prospect. Reuse the existing `getBlueprintPayload`/`generateBlueprint` engine; just bypass the public entitlement check for admin/internal callers.
- **Grant access dialog**: keep it for granting internal users (admin or internal role) access to Blueprint/OS for testing/demos.
- **Internal user access**: users with the `internal` role can log in and see the full Blueprint, roadmap, copilot, etc., so Jeff or a sales rep can walk through the report live with a prospect.

### 6. Routes and security

- Keep the existing authenticated route guard (`/_authenticated/route.tsx`).
- Ensure Blueprint routes (`/dashboard`, `/blueprint`, `/roadmap`, `/copilot`, `/settings`) are reachable by free users, but server-side entitlement checks return the locked preview where applicable.
- Remove public access to `/checkout/success` or redirect it; only internal users should hit checkout/grant flows.
- Audit `FeatureGate` and `LockedFeature` usage to confirm they now show the "Book a call" CTA instead of a purchase CTA.

### 7. Data and compliance

- Existing purchases/subscriptions remain in the database for accounting but no longer grant access.
- Decide whether existing paid customers should be refunded, migrated to free, or granted internal access (see Decision 1).
- Update refund policy and terms if the paid product is removed from public sale.

## Decisions to confirm before implementation

1. **Existing paid customers**: do you want to refund them, convert them to free, or grandfather them with internal access? This affects whether we revoke existing entitlements.
2. **Internal role name**: should it be `internal`, `sales`, `analyst`, or something else? The UI and admin grant dialog will use this label.
3. **Pricing page fate**: repurpose the URL `/pricing` to `/work-with-me` (with redirect) or keep `/pricing` but replace the content with consulting info?
4. **Contact page tracking**: do you want to add an event when a user clicks "Book a call" so you can attribute leads to persona/assessment source?
5. **OS future**: is Publisher OS still planned for a future internal launch, or should it be removed from public messaging entirely?
