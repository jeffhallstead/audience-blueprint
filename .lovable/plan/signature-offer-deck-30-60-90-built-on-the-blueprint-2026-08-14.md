# Signature Offer Deck — 30/60/90 built on the Blueprint

## Is it viable?

Yes. The Blueprint already contains the exact structure a signature service needs, and it's real logic, not marketing:

- Three sequenced 90-day phases (Foundation → Execution → Optimization), each with an objective, key activities, and success metrics, calibrated to the client's maturity tier.
- Six scored dimensions that name where the gap is.
- Eight behavioral personas that let you say "you're this pattern, here's what that costs you."
- A KPI set with targets, so month 3 ends with proof rather than opinion.

That means your offer can be described as a diagnostic-led engagement: the Publisher Test names the pattern, the Blueprint sets the 90-day plan, and you run it with them. The deck's job is to make that legible before a prospect has taken the test.

## What gets built

A branded PDF deck (Executive Obsidian: near-black covers, indigo-violet accent, Outfit + Plus Jakarta Sans), landscape 16:9, generated by a committed script so it can be regenerated when the offer changes. Designed to be presented live on a call, one idea per slide.

### Slide sequence (~14 slides)

1. Cover — the signature offer name + "A 90-day engagement"
2. The problem — audience built on rented channels; effort without compounding
3. The pattern — the six dimensions of publisher maturity, and where most brands stall
4. Which pattern are you? — the behavioral personas, condensed to a recognizable grid
5. How the engagement works — Diagnose → Blueprint → Run (one line each)
6. Days 1–30: Foundation — objective, what we do, what you get, how we measure it
7. Days 31–60: Execution — same structure
8. Days 61–90: Optimization — same structure
9. What you walk away with — deliverables list (Publisher Index score, full Blueprint, 90-day plan, KPI dashboard, executive readout)
10. How we measure success — the KPI table with targets
11. Who this is for / not for — qualification slide
12. Why Jeff — media background, credibility line
13. Starting point — take the Publisher Test, then a readout call
14. Close — contact + URL

Content for slides 3, 4, 6–8, and 10 is pulled from the live rule engine and persona library rather than written fresh, so the deck and the product say the same thing.
